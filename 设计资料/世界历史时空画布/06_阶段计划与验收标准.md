# 06｜阶段计划与验收标准

## 1. 总体阶段

| 阶段 | 名称               | 主要成果                                   | 进入条件         |
|:-----|:-------------------|:-------------------------------------------|:-----------------|
| P0   | 前期验证           | 地图验证、数据源样本验证                   | 当前阶段         |
| M0   | 地图基础           | 正式地图模块、样式切换、历史图层基础       | P0 验收通过      |
| M1   | 地理数据基础       | PostGIS 地点模型、坐标规范、第一批地点数据 | M0 方案冻结      |
| M2   | 核心对象管理       | 地点、人物、事件 CRUD 和关联               | 核心数据模型冻结 |
| M3   | 时间—地图联动      | 时间轴、地图筛选、对象联动、人物地点观察   | M2 基础能力通过  |
| M4   | 数据扩充与整体验收 | 扩大数据覆盖、稳定性、Docker 部署和备份    | M3 通过          |

## 2. P0 验收

### WB-001 地图技术验证

必须有： - 可运行 Demo。 - 真实测试环境和测试区域记录。 - 样式清单及实际
style ID。 - Outdoor 地形和标签观察。 - Satellite / Hybrid 细节表现。 -
地图视野保持测试。 - 历史图层叠加测试。 - attribution 和凭证安全检查。 -
账号额度与费用结论。

### WB-002 数据源验证

必须有： - 四个数据源真实字段清单。 - 样本数据和来源版本。 -
坐标系与轴顺序确认。 - 覆盖范围和时间范围。 - 许可核查。 -
样本重叠与候选匹配分析。 - 字段映射表。 - 第一批导入建议。

P0 结束后，Owner
对地图供应、数据来源组合、首批数据范围和后端详细设计做最终确认。

## 3. 正式开发阶段验收原则

### M0 地图基础

- MapTiler 样式接入正确。
- 默认 Outdoor。
- 样式切换保留视野。
- 历史点位可叠加、点击和显示详情入口。
- 不影响底图 attribution。
- 地图组件与业务对象模块解耦。

### M1 地理数据基础

- 地点可新增、查看、编辑、删除。
- 支持历史名称、别名、坐标、定位精度、来源。
- 支持 Point 和必要的区域几何。
- 坐标 CRS 统一且可追溯。
- 人工修正不会被后续导入静默覆盖。

### M2 核心对象管理

- 人物、事件 CRUD。
- 事件与人物、地点多对多关联。
- 人物与活动地点关联。
- 关联增删后详情和地图展示一致。
- 删除有影响提示，无静默级联删除。

### M3 时间与地图联动

- BCE/CE 转换和排序正确。
- 内部时间整数不向界面直接显示。
- 单年、区间和持续事件筛选正确。
- 地图和列表同步更新。
- 点击事件、人物、地点可以相互跳转。
- 未知时间和未定位数据有合理展示方式。

### M4 数据扩充与整体验收

- 数据源版本、导入批次和来源可追溯。
- 失败数据可定位。
- 不同来源的同名异地不会错误合并。
- Docker Compose 可启动和停止。
- 数据持久化、备份和恢复验证通过。
- 关键功能有回归测试。

## 4. 每个阶段的交付格式

每个里程碑至少交付： 1. 完成范围和未完成范围。 2. 变更文件清单。 3.
架构或数据结构变更说明。 4. 自动化测试结果。 5. 关键人工验收步骤和截图。
6. 已知问题和风险。 7. 如何运行、如何复现。 8. 是否需要 Owner 决策。

## 5. 变更控制

- 不得把建议功能直接加入当前阶段。
- 新增需求先列影响、成本、风险和替代方案。
- 发现架构性问题时优先处理根因，不用补丁掩盖。
- 不得未经批准改变技术栈、数据库模型核心边界或数据治理原则。
- 未经 Owner 验收，不进入下一阶段。
