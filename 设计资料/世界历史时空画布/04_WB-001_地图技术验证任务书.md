# WB-001｜MapTiler + MapLibre 地图技术验证任务书

**优先级：** P0  
**性质：** 独立技术验证，不是正式产品开发  
**执行方式：** 可与 WB-002 并行  
**交付后：** 等待 Owner 验收，不自动进入正式工程施工

## 1. 验证目标

确认 MapTiler Cloud + MapLibre GL JS
能否满足《世界历史时空画布》的地图体验要求： - 国内裸连加载流畅。 -
全球主要区域可正常浏览。 - Outdoor
地形、河流、山峰、地名信息满足读史用途。 - 电子地图和卫星地图可切换。 -
样式切换不丢失当前地图视野。 - 凭证使用方式安全、成本可控。

用户已在自己的环境中初步测试
MapTiler，反馈裸连加载顺利、Outdoor/电子地图/卫星图体验较好。此次验证是工程化确认，不是重新做供应商大比选。

## 2. 范围

### 必须完成

1.  使用 MapLibre GL JS 建立独立最小地图页面。
2.  接入用户账号当前可用的 MapTiler 样式。
3.  默认 Outdoor。
4.  至少验证 Outdoor、Streets / Base、Satellite、Hybrid
    中账号实际可用的样式。
5.  支持地图拖动、缩放、样式切换。
6.  样式切换保留中心点、缩放级别和旋转/倾斜状态（若页面启用）。
7.  保留 MapTiler attribution。
8.  在地图上增加少量临时测试标记，证明后续自有历史图层可以叠加。
9.  输出测试证据和结论。

### 不做

- 不创建正式业务项目。
- 不接入 Spring Boot。
- 不创建正式数据库。
- 不实现历史时间轴。
- 不下载或处理历史数据。
- 不自建瓦片服务。
- 不隐藏 attribution。
- 不把 token 写入代码或报告。

## 3. 测试区域

至少覆盖： - 中国：西安或洛阳附近。 - 欧洲：罗马或雅典附近。 -
北美：纽约附近。 - 中东：耶路撒冷附近。

测试点只是地图服务覆盖与加载验证，不表示历史地点数据已经确认。

## 5. 凭证安全

- 先确认用户现有凭证是浏览器端 API key 还是服务端 Service token。
- 浏览器地图显示使用 API key；将 key 配置在本地 `.env.local`，不提交
  Git。
- 在 MapTiler 控制台限制 Allowed HTTP origins。
- `VITE_` 变量构建后会暴露给浏览器，因此不能把它当作服务端秘密。
- Service token 不得进入浏览器。
- 不在聊天、截图、日志或报告中展示真实凭证。
- WorkBuddy 不应要求用户在聊天中粘贴
  key；如需凭证，由用户在本地环境自行配置。

## 6. 测试环境与可复现性

交付中记录： - 操作系统、浏览器版本。 -
测试日期和网络方式（裸连/代理；本轮目标是用户实际裸连环境）。 -
测试区域和地图缩放级别。 - MapTiler 样式名称和实际 style ID（不得包含
key）。 - 首次加载和切换样式的观察结果。 - 浏览器 Network
中失败请求类型（URL 中如含 key，截图前必须遮蔽）。 - 关键截图。

不要虚构毫秒级性能数字。若没有可靠自动计时工具，明确标记为人工观察。

## 7. 通过标准

- 所有选定样式可以在用户目标网络环境下正常加载。
- 四个测试区域均可浏览，无持续性空白或严重缺瓦片。
- Outdoor 地形和地名足以支持一般历史地理观察。
- Satellite 在主要测试区域有可用细节；区域差异如实记录。
- 样式切换保留视野。
- 临时历史图层可正常叠加。
- attribution 可见。
- key 未泄漏，且已设置来源域名限制。
- 账号计划和费用规则已查明，或明确列出尚未查明项。

如果某一地区或样式不达标，先报告具体范围和影响，不得直接替换地图供应商。
