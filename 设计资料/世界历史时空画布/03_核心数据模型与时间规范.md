# 03｜核心数据模型与时间规范

## 1. 时间模型最终决策：A

**时间是统一维度，不是独立业务实体。**

不建立独立 `time` / `historical_period` 核心表，不提供时间对象
CRUD。时间作为事件、人物生卒、地点名称有效期、人物活动地点关系等对象的属性保存。

时间轴是一个交互和查询模块，负责选择时间范围、筛选数据和控制地图显示。

若未来需要”春秋时期”“战国时期”等快捷入口，可以用配置化筛选预设或轻量分类元数据实现，不因此把时间升级为独立核心对象。

## 2. 公元前 / 公元后内部纪年

采用天文学纪年整数（Astronomical Year
Numbering），便于跨越公元前后进行比较和排序。

换算： - 公元前 n 年（BCE n）→ 内部年份 `1 - n` - 公元后 n 年（CE n）→
内部年份 `n`

示例：

| 界面年份       | 内部整数 |
|:---------------|:--------:|
| 公元前 771 年  |   -770   |
| 公元前 2 年    |    -1    |
| 公元前 1 年    |    0     |
| 公元后 1 年    |    1     |
| 公元后 2026 年 |   2026   |

界面不得显示”公元 0 年”。内部整数 0 仅用于计算。

## 3. 时间区间规则

V1 以年份为核心精度。每个带时间信息的对象使用： - `start_year_astro` -
`end_year_astro` - `time_precision` - `time_original_text` - `time_note`

规则： - 单年事件：start = end。 - 持续事件：start 和 end
分别记录起止年份。 - 年代不确定：在可支持的情况下用时间范围表达，并设置
approximate / range 精度。 - 完全未知：起止年份均为空，precision =
unknown。 - 不得为了填充时间轴而编造年份。 - 区间端点按包含式处理。 -
月、日只有在资料确实提供且格式可确认时才扩展，不要求 V1
完成复杂历法换算。

时间范围查询重叠规则：

`event.start_year_astro <= selected_end AND event.end_year_astro >= selected_start`

未知年代事件不进入普通年份查询，可通过独立筛选查看。

## 4. 时间属性应用位置

| 对象                       | 时间属性                                    |
|:---------------------------|:--------------------------------------------|
| event                      | 事件开始/结束年份、精度、原始日期文本、说明 |
| person                     | 出生年份、死亡年份及各自精度                |
| place_name                 | 名称有效起止年代                            |
| person_place               | 人物与地点关系的有效起止年代                |
| event_place / event_person | 如关系本身有明确有效期，可选记录；不强制    |

CRS、版本和批次。正式表保存当前采用的规范化数据。

## 6. 地点坐标与空间规范

- 业务数据库统一以 WGS84 / EPSG:4326 作为标准空间参考。
- 原始坐标值和原始 CRS 必须保留。
- 不能确认坐标系的数据不得直接进入正式地图位置。
- 不同坐标体系（例如 WGS84、GCJ-02、BD-09）不得直接混用。
- `geometry` 可表示 Point、Polygon 或 MultiPolygon。
- `representative_point` 用于地图默认标记，不代表边界或遗址精确位置。
- `precision` 表达定位精度等级；`uncertainty_m` 仅在有依据时填写。
- 现代地名是辅助参考，不是地点成立的前提。

## 7. 关系规则

- 一个事件可以关联多个人物和多个地点。
- 一个人物可以关联多个事件和多个活动地点。
- 一个地点可以有多个历史名称及不同年代的名称沿革。
- 同名地点不自动合并。
- 人物路线只根据已录入且有时间顺序的地点生成示意连线；不能把直线连线描述成真实行进轨迹。
- V1 不建设国家/政权疆域实体体系。

## 8. 数据冲突和人工修正

不建设复杂自动裁决系统。

原则： 1. 每个历史地点维护一个当前正式主记录。 2.
原始来源记录保留来源名、外部 ID、原始坐标、原始 CRS 和导入批次。 3.
根据来源覆盖范围和抽样质量选定首批采用数据。 4.
用户可以直接编辑正式主记录。 5. 后续导入不得无提示覆盖用户手工修改。 6.
名称相同不等于同一地点，自动匹配只能生成候选，不得直接强制合并。

## 9. 删除规则建议

- 不允许无提示级联删除关联对象。
- 删除前显示关联事件、人物或地点。
- 存在关联时先解除关联或由用户明确确认后续处理。
- 硬删除/软删除最终在数据库详细设计阶段冻结。
