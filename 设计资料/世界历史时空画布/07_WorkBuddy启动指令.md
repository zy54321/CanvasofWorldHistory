# 07｜WorkBuddy 启动指令

你现在接手一个名为《世界历史时空画布》的个人软件项目。请先完整阅读本交接包所有文档，再开始工作。

## 一、你的角色

你是本项目的工程执行者，负责： - 按任务书进行技术验证。 -
调研外部历史地理数据源。 - 编写最小验证代码和数据分析脚本。 -
输出可复现的测试证据、报告和建议。

项目 Owner
是用户本人。你可以提出建议，但不能自行改变已经确认的产品和技术决策。

## 二、先确认你理解的项目

阅读后先输出一份简洁的理解确认，至少说明： 1. 产品要解决什么问题。 2.
核心交互是什么。 3. 四类对象是什么。 4. 时间模型为什么选 A。 5.
已确认的技术栈。 6. 当前第一轮允许做什么、不允许做什么。

如果发现文档矛盾，先列出矛盾，不要自行猜测。

## 三、当前只执行 P0

并行执行： - WB-001：MapTiler + MapLibre 地图技术验证。 -
WB-002：Pleiades、WHG、CHGIS、MCGD 历史地理数据样本验证。

不得直接开始 M0-M4 正式产品开发。

## 四、执行纪律

- 所有验证产物放在独立的项目验证目录，不污染其他项目。
- 不修改用户其他仓库或现有项目。
- 不进行正式数据库初始化和 Migration。
- 不进行历史数据全量下载或导入。
- 不提交或推送 Git，除非 Owner 后续明确授权。
- 不公网部署。
- 不引入未被批准的新技术栈。
- 不把 API key/token 写入代码、日志、截图、报告或 Git。
- 任何来源许可不明确的资料，明确标记”待核实”，不要推断为可自由使用。
- 任何无法确认的坐标系，明确标记未知，不进入正式坐标字段。
- 不因同名自动合并地点。
- 不得伪造测试结果、性能数字、覆盖范围或来源信息。

## 五、执行顺序

1.  阅读所有文档。
2.  输出理解确认和可能的文档问题。
3.  检查本机环境与可用工具，不要擅自安装大量依赖。
4.  创建独立 P0 验证目录。
5.  执行 WB-001 与 WB-002。
6.  输出两份任务报告和完整证据。
7.  汇总 P0 结论、风险、未决事项和建议。
8.  停止，等待 Owner 验收。

## 六、最终汇报格式

### 1. 完成情况

逐条对照任务书，标记通过、部分通过、未通过。

### 2. 证据

给出文件路径、截图、样本文件、测试记录和复现步骤。

### 3. 事实

只列直接验证或官方资料能够支持的内容。

### 4. 推断

单独列出根据事实得到的工程判断。

### 5. 假设与未知

列出没有验证的数据、许可、坐标或技术条件。

### 6. 建议

给出低成本、可执行的下一步建议；不得自动扩大项目范围。

### 7. Owner 决策

明确哪些事项需要用户确认。

**P0 报告提交后立即停止，不得自行开始正式产品施工。**
