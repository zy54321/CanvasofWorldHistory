### 3.4 密钥剥离（新增能力）

原实现把 `VITE_MAPTILER_API_KEY` 通过 `define` 内联进 JS，实测 `dist/assets/index-*.js` **确实含真实 key**（20 字符）。

改为运行时注入：

| 改动 | 内容 |
|---|---|
| `frontend/public/config.js`（新增） | 空占位 `window.__ENV__ = window.__ENV__ \|\| {};`，会随构建进入 dist |
| `frontend/index.html` | 在 `main.ts` 之前引入 `<script src="./config.js">` |
| `frontend/src/map/basemaps.ts` | 取值顺序：`window.__ENV__.MAPTILER_KEY` → 构建期 `__MAPTILER_KEY__` → 空（降级无底图） |
| `frontend/vite.config.ts` | 新增 `CANVAS_STRIP_MAPTILER_KEY=1` 开关，构建时强制置空 |

验证：

```
真实 key 在 dist 中的命中数：0
dist/config.js 内容：window.__ENV__ = window.__ENV__ || {};
```

**效果**：Release 包零密钥；部署时在 `web/config.js` 写入 key 即可启用底图，无需重新打包。无 key 时地图降级为经纬网，界面有明确提示（原有降级逻辑）。

### 3.5 单 Jar 同源部署

先做实验验证（手工把 dist 复制进 `target/classes/static` 再打包），确认可行后固化为 Maven Profile。

`code/backend/pom.xml` 新增 `with-web` profile：

```xml
<profile>
  <id>with-web</id>
  <build>
    <resources>
      <resource><directory>src/main/resources</directory></resource>
      <resource>
        <directory>../frontend/dist</directory>
        <targetPath>static</targetPath>
        <filtering>false</filtering>
      </resource>
    </resources>
  </build>
</profile>
```

### 施工中发现并修复的 5 个缺陷

| # | 缺陷 | 后果 | 修复 |
|---|---|---|---|
| 1 | `java -version` 输出走 stderr，在 `ErrorActionPreference='Stop'` 下被转成终止性错误 | 永远报「未找到 java」，流程无法开始 | 调用前后临时切 `Continue`，并用 `Format-GitLine` 字符串化 |
| 2 | `manifest.json` 用 `Set-Content -Encoding UTF8` | 带 BOM，`json.load` / `jq` 可能解析失败 | 改用 `WriteAllText` + `UTF8Encoding($false)` |
| 3 | pom 版本正则匹配到第一个 `<version>` | 记录成 `3.5.16`（Spring Boot parent 版本） | 先剔除 `<parent>` 段再匹配 → 正确得到 `0.1.0` |
| 4 | 迁移列表按字符串排序 | `V1, V10, V2, V3...` | 按迁移编号数字排序 |
| 5 | `SHA256SUMS.txt` 用 CRLF 写入 | `sha256sum -c` 把 `\r` 当成文件名，**18 个全部 FAILED** | 改为 LF 换行 |

第 5 个最关键：脚本内部的复核逻辑不依赖 `sha256sum`，所以内测通过，但用标准工具验证会全线失败。已修复并复验 18/18 OK。
